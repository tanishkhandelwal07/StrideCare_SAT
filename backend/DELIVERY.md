# SOS and report delivery

The default practice app never sends SOS messages. A connected mobile build can select a real peripheral with `--dart-define=CARE_BLE_DEVICE_ID=<platform device identifier>`. Use a configured Firebase project, an authenticated patient and the matching firmware contract. Keep the app running and connected during the countdown. The ten seconds start when the phone records the fall. Acknowledging before expiry cancels the request. A disconnected cane, suspended app, unavailable network or rejected message can prevent delivery. The app is not an emergency service.

The first emergency contact receives the SOS and, with separate permission, one daily activity SMS. The assigned physio receives a weekly activity SMS. SMS reports contain the patient's chosen display name, step count, walking minutes and walk count. The existing PDF remains a separate export. Missing synced walks are described as missing data. The scheduled job runs at 07:15 India time for the previous day and, on Mondays, the previous Monday–Sunday. Late uploads after dispatch do not revise the SMS.

## Provisioning

1. In a production Firebase project enable Firestore, Functions and Scheduler with billing. Use a separate test project and test recipients first. Never enable delivery routes for practice patients or accounts that sync simulated walks.
2. Install dependencies in backend/functions with npm install. Configure TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN and TWILIO_FROM using firebase functions:secrets:set. Register the destination-country sender and approved message templates with the provider before enabling routes. The generic SMS bodies here need provider approval or adaptation for India.
3. With trusted admin tooling, verify telephone ownership, consent for each purpose and clinician assignment. Create the server-only document deliveryRoutes/{patientUid} with displayName, contactPhone (the verified first emergency contact in E.164), physioUid, and separate boolean sosEnabled, dailyEnabled and weeklyEnabled fields. Store the verified clinician phone in deliveryPhysios/{physioUid}. Ensure clinicians/{physioUid}/patients/{patientUid} exists. Changes to local contacts do not update these routes automatically. Disable affected routes until a changed recipient has been verified. Revoke a purpose by setting its flag false.
4. Deploy with firebase deploy --only firestore:rules,functions --project YOUR_PROJECT. Check provider acceptance using a consenting test recipient and verify the message arrives. Inspect the private deliveries subcollection of the patient's route for each attempt. The app does not claim receipt. Provider acceptance does not confirm handset delivery. If an attempt is interrupted, reconcile it with the provider before enabling a retry. No provider account, production recipients, or cloud resources are provisioned by the repository.
